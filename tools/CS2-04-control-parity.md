## Safe parallel implementation boundaries

The current frontend is a single HTML file with shared globals. **Do not assign multiple agents direct overlapping edits to it.** Root should preserve the exact current runtime/source first, then use one shell integrator for markup/import wiring and explicit module boundaries.

| Proposed owner | Exclusive implementation boundary after assignment | Shared contracts / integration rule |
| --- | --- | --- |
| ITEMS | Filter state/query adapter, whole-dataset sort/bounds/paging, preset compatibility; isolated tests | Own new `restoration/items.*` module/tests or narrowly handed-off HTML regions only. Coordinate API schema with API owner; do not change canonical cash semantics. |
| IMPORT/EXPORT + NOTES | Parser/export pure helpers, duplicate fixtures, local note restoration helper/tests | Preserve storage keys and import identity/qty semantics. Submit helper module + markup snippet; integrator mounts it. No live saves/deletes. |
| MOBILE/ACCESSIBILITY | Dedicated CSS module and keyboard/ARIA helper/test plan | Scope selectors to restored widget classes; do not globally hide overflowing tables. Avoid changing data/render functions. |
| OVERVIEW | Allocation/brief/risk/rankings/return-chart modules and synthetic fixtures | Read accepted view-model contract; never call legacy full-data writers. One markup handoff to integrator. |
